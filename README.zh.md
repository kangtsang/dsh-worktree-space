# Worktree Space

DeepSeek Harness 的 Worktree Space 插件：一个任务横跨一个或多个仓库，每个仓库以 Git worktree 的形式
检出一份，共用同一个分支，放在源码树之外的任务空间目录中，并注册为带独立会话的 DSH 工作区。

## 功能

- **从会话中创建任务。** 选择源码根、命名任务、勾选要横跨的仓库、指定任务空间位置。每个仓库都会得到
  一份位于 `<分支前缀>/<任务名>` 上的 worktree（前缀默认 `feat/`），起点可以是各仓库当前的 HEAD，
  也可以是指定的分支或提交。
- **注册为工作区**，名称是 `<上级>/<任务名>`，并打开一个工作目录即该任务空间的新会话 —— Agent 可以跨
  仓库改代码，而不会动到源码检出。
- **管理页面**（侧边栏底部的 Worktree Space 入口）有三个视图：
  - **任务视图**：按任务聚合各仓库的明细（分支、改动数、锁定 / 可清理状态）；
  - **工作区视图**：每个工作区能否作为 worktree 任务空间的来源，以及它包含几个仓库；
  - **仓库视图**：扫描到的每个 Git 仓库及其链接的 worktree。

  三者都支持搜索与「待处理」筛选（筛选出有改动、已锁定、可清理或状态异常的行）；每行的箭头可折叠
  单项，筛选旁的按钮一次折叠或展开全部。
- **结束任务**：在任务行上结束 —— 默认把各仓库的分支合并回主线，移除 worktree，把任务空间内的文档存入
  `archived-docs/<工作区名>-<YYYYMMDD-HHMMSS>`（取消勾选则任务空间内文件全部删除），最后移除工作区
  注册。该工作区里还有会话在运行时会拒绝结束。
- **结束任务空间** 也出现在工作区列表自己的 `⋯` 菜单里 —— 仅对确实是任务空间的目录出现。
- **无需额外服务。** 两个入口、扫描深度与单次扫描的目录上限都在插件自己的配置里调整（见「配置」）。
  支持 DSH 主题，界面中英文随 DSH 的语言设置切换；插件列表里的名称、描述与图标也由本插件提供。

## 任务目录结构

```text
<任务空间根目录>/
├── <任务名>/                      任务空间 —— 同时是会话的工作目录
│   ├── README.md                  任务的分支、起点与约定
│   ├── <仓库 A>/                  位于 <分支前缀>/<任务名> 的 worktree
│   └── <仓库 B>/                  同名分支的 worktree
└── archived-docs/
    └── <上级>-<任务名>-20260926-020933/    归档文档时存入此处
```

移除 worktree 不会删除对应的 Git 分支；结束任务会先把分支合并回去，再移除 worktree。

## 兼容性

基于 DSH **0.1.7-rc.1** 客户端契约构建（web profile）。已在 `0.1.7-rc.1` 上验证：宿主 RPC 路由
注册成功，客户端 bundle 无需改动即可加载，插件列表中的名称 / 描述 / 图标与配置区均正常显示。

## 使用

### 安装

```sh
# 本地 checkout（开发时）
dsh plugin --profile web add link:/absolute/path/to/dsh-worktree-space

# 从 npm（发布后）
dsh plugin --profile web add dsh-worktree-space
```

profile 设为 `patchReload: live` 时无需重启即可重载；否则重启 `dsh web`。

### 配置

在 **侧边栏 → 插件 → Worktree Space** 里调整，与其它插件的配置在同一处，改完即时生效：

| 设置 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| 侧边栏入口 | 显示 / 隐藏 | 显示 | 侧边栏底部的 Worktree Space 入口 |
| 设置面板入口 | 显示 / 隐藏 | 隐藏 | 是否同时在设置面板里提供入口；两个入口互相独立 |
| 扫描深度 | 1–5 层 | 2 层 | 从每个工作区根目录向下扫描的层数（根目录本身不计入） |
| 最大遍历目录数 | 500 / 1000 / 2000 / 3000 / 5000 / 10000 | 1000 | 一次扫描最多读取的目录数，超过则提示改用更精确的工作区 |

扫描**永远覆盖全部工作区**（没有范围开关），按**广度优先**逐层进行，每层最多 8 个目录并发读取；
在任意层级发现 `.git` 即认定为仓库，`node_modules`、`dist`、`build`、`vendor` 等目录与隐藏目录会被
跳过（`.worktrees` 除外）。

### 创建任务

<img src="docs/new-worktree-space.png" alt="新建 Worktree Space" width="598">

1. 在会话中，点击输入框上方的 **新建 Worktree Space**。
2. 命名任务 —— 会转为小写，空格、中文与其他字符用连字符代替（`hotfix-placeorder`）；名称不合法时会
   直接指出违反了哪条规则。
3. 设置任务空间位置。它必须位于源码树之外，界面会填好推荐路径。
4. 勾选任务要横跨的仓库，并选择分支起点。
5. 点击 **创建并打开**。新工作区会带着一个位于该任务空间的会话打开。

若任务空间已经建好、但工作区注册失败，对话框会明确说明，并允许重试注册。

### 管理任务

<img src="docs/manage-worktree-space.png" alt="管理页面：任务 / 工作区 / 仓库三个视图" width="890">

打开 **管理页面**（侧边栏底部的 Worktree Space 入口）。三个视图的差异见「功能」一节：任务视图看每个
任务及其仓库明细，工作区视图看哪些工作区能建任务空间，仓库视图看扫描到的每个 Git 项目及其 worktree。
右侧统计随视图切换（`N 个任务` / `N 个工作区` / `N 个仓库 · M 个 Worktree`），搜索或筛选时会显示
`可见 / 总数`。

### 结束任务

<img src="docs/finish-task.png" alt="结束任务对话框" width="612">

在任务行上点 **结束任务**，或在工作区列表的 `⋯` 菜单里点 **结束任务空间**。对话框会在动手之前说明会
发生什么：未提交的文件、待合并的提交、合并目标分支，以及任务空间内的文档（确实有可归档内容时才会出现
「归档文档」选项）。默认勾选「合并回主线」；「删除分支」和「强制」默认不勾选。
